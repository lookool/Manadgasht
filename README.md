# مانادگشت

سایت دفتر خدمات مسافرتی «مانادگشت» — فروش تور، هتل و پکیج ترکیبی
تور+هتل. ظاهر بر اساس رنگ/فونت/محتوای واقعی manadgasht.com بازسازی
شده، با چند المان بصری الهام‌گرفته از arandtour.com (کارت‌های
دسته‌بندی و بنر پیشنهاد ویژه) برای جذابیت بیشتر.

## معماری کد

پروژه به‌صورت لایه‌ای نوشته شده تا هم تست‌پذیر باشه، هم افزودن فاز ۲
(پنل‌ها + کمیسیون) بدون به‌هم‌ریختن کد فعلی ممکن باشه:

```
cmd/server/main.go     فقط "وایرینگ": همه‌چیز رو به هم وصل می‌کنه و سرور رو بالا میاره
internal/config/       خواندن تنظیمات از .env
internal/database/     اتصال به Postgres + مایگریشن خودکار جدول‌ها
internal/models/       مدل‌های دیتابیس (Package، BlogPost، User، Admin، Agent، ...)
internal/repository/   تنها لایه‌ای که مستقیم با دیتابیس/GORM صحبت می‌کنه
internal/service/      منطق تجاری؛ هندلرها فقط با این لایه کار می‌کنن
internal/handlers/     کنترلرهای HTTP (ورودی/خروجی، رندر تمپلیت)
internal/router/       تعریف مسیرها (جدا از main.go)
web/templates/         فایل‌های HTML (Go html/template)
web/static/            CSS و عکس‌ها
```

قانون ساده: **هندلر هیچ‌وقت مستقیم به دیتابیس دسترسی نداره**، همیشه از
طریق service. و service هم مستقیم gorm صدا نمی‌زنه، از طریق repository.

## این فاز چی داره؟

**فاز ۱ (رابط عمومی سایت):** صفحه‌ی اصلی با هیرو+جست‌وجو، دسته‌بندی
سریع، لیست و جزئیات تور/هتل، بلاگ، درباره ما، تماس با ما، ویجت شناور
تماس/واتساپ.

**فاز ۲ (احراز هویت + کمیسیون همکاران) — همین الان اضافه شد:**
- ثبت‌نام/ورود کاربر عادی (`/register`, `/login`) — با امکان وارد کردن
  کد معرف یک همکار موقع ثبت‌نام
- ثبت‌نام/ورود همکار یا «تورلیدر» (`/agent/register`, `/agent/login`)
  — نام، کد ملی، شماره تماس، شماره کارت؛ به هر همکار یک کد معرف یکتا
  (مثل `MG-7K2N4X`) خودکار داده می‌شود
- پنل کاربری (`/account`): تاریخچه‌ی خریدها
- پنل همکار (`/agent/dashboard`): کد معرف، موجودی کیف‌پول، تاریخچه‌ی
  کمیسیون‌ها، ثبت درخواست برداشت (با شماره کارت و شبا)
- خرید آنلاین یک تور/هتل توسط کاربر لاگین‌کرده → اگر با کد معرف یک
  همکار ثبت‌نام کرده باشد، درصد کمیسیون (تنظیم‌شده بر اساس نوع تور/هتل)
  خودکار به موجودی همان همکار اضافه می‌شود
- خرید همکار از موجودی کیف‌پول خودش (بدون کمیسیون)
- رمزهای عبور با bcrypt هش می‌شوند؛ نشست‌ها (Session) با کوکی امن
  (HttpOnly) مدیریت می‌شوند

نکته‌ی مهم: **درگاه پرداخت واقعی هنوز وصل نیست.** خرید آنلاین فعلاً
مستقیم به‌عنوان «تأییدشده» ثبت می‌شود تا جریان کمیسیون از همین حالا
قابل تست باشد؛ وصل‌کردن یک درگاه واقعی (زرین‌پال یا مشابه)، قدم بعدیه.
همچنین فرم‌ها هنوز محافظت CSRF ندارن — برای رفتن به حالت پروداکشن باید
اضافه بشه.

**چیزی که هنوز نیست:** پنل ادمین (مدیریت تور/هتل/بلاگ/تورلیدرها،
تأیید یا رد درخواست‌های برداشت، تغییر درصد کمیسیون از رابط کاربری)،
درگاه پرداخت واقعی، و محافظت CSRF.

## راه‌اندازی

۱. مطمئن شو Go و PostgreSQL نصب هستن.
۲. یک دیتابیس با نام `manadgasht` توی PostgreSQL بساز. **اگر قبلاً این
   دیتابیس رو برای فاز ۱ ساخته بودی، چون ساختار جدول Order عوض شده،
   بهتره دیتابیس رو پاک و از نو بسازی** (چون هنوز پنل ادمین نداریم و
   دیتابیس خالیه، این کار بدون از دست رفتن داده‌ی واقعی انجام میشه).
۳. فایل `.env.example` رو کپی کن، اسمش رو بذار `.env`، و `DB_PASSWORD`
   رو با پسورد واقعی پر کن.
۴. توی ترمینال، داخل پوشه‌ی پروژه:

```bash
go mod tidy
go run cmd/server/main.go
```

۵. مرورگرت رو باز کن روی `http://localhost:8080`.

با اجرای اول، جدول‌های دیتابیس خودکار ساخته می‌شن، و درصد کمیسیون
پیش‌فرض (۵٪ تور، ۲٪ هتل، ۴٪ پکیج ترکیبی) هم خودکار تنظیم میشه. برای
تست کامل جریان کمیسیون: یک همکار از `/agent/register` بساز، کد معرفش
رو کپی کن، یک کاربر از `/register` با اون کد معرف بساز، بعد از صفحه‌ی
یک تور روی «خرید آنلاین» بزن — باید موجودی همکار تو `/agent/dashboard`
بالا بره.

## نکته درباره‌ی go.sum

چون این پروژه بدون اتصال به اینترنت آماده شده، فایل `go.sum` ساخته
نشده. اولین باری که `go mod tidy` رو روی سیستم خودت بزنی، Go خودش
کتابخونه‌ها رو دانلود و این فایل رو می‌سازه؛ کاملاً عادیه.

## ورژن‌بندی با Git

این پروژه از همین الان با `git` مقداردهی اولیه شده و شامل چند کامیت
مرحله‌به‌مرحله‌ست (پیکربندی → مدل‌ها → repository → service → هندلرها
→ رابط کاربری) که با:

```bash
git log --oneline
```

می‌تونی ببینیشون. برای بالا بردن روی گیت‌هاب:

```bash
git remote add origin <آدرس ریپوی خودت روی گیت‌هاب>
git branch -M main
git push -u origin main
```

از این به بعد هم برای هر تغییر بزرگ (مثلاً فاز ۲: پنل ادمین)، بهتره
یک کامیت جدا با پیام مشخص بزنی؛ می‌تونیم این کار رو هم مرحله‌به‌مرحله
با هم انجام بدیم.

## فاز بعدی

- پنل ادمین: مدیریت تور/هتل، بلاگ، تورلیدرها، تأیید/رد درخواست‌های
  برداشت، و تنظیم درصد کمیسیون از رابط کاربری
- اتصال درگاه پرداخت واقعی برای خرید آنلاین
- محافظت CSRF روی فرم‌ها
- رزرو آنلاین کامل‌تر (انتخاب تاریخ، تعداد نفرات و ...)
